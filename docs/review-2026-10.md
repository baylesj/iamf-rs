# October 2026 review: changes and upstream notes

In October 2026 we reviewed the whole repository, fixed what we found, and
added a regression test for each fix. This page lists:

- [what changed](#changes), one commit per fix;
- [issues that may also exist upstream](#possible-upstream-issues), for
  filing with the projects we port from or depend on;
- [findings that needed no change](#checked-no-change) and
  [what is still open](#open-items).

Commits are named by subject; `git log --grep "<subject>"` finds them.
Every regression test fails without its fix (each was checked against the
code before the fix) unless the table says otherwise.

## How the issues were found

- Code review of every crate, in four parallel passes (parser, decoder
  drivers, DSP and rendering, FFI and tooling).
- Hand-built streams that reproduce each finding, now in
  `tools/iamfdec/tests/regressions.rs` and the unit tests named below.
- A frame-length mutation probe over all conformance vectors, and a
  stable-toolchain mutation fuzzer with the IAMF v2.0 profiles enabled.
- After the fixes: cargo-fuzz on all four targets with debug assertions
  (about 10.5 million executions over 5 to 10 minutes per target, including
  the v2.0, reset and batch paths
  for the first time). No crashes.

## Changes

### Crashes, hangs and memory blow-ups from untrusted input

| Problem | Fix (commit subject) | Regression test |
| --- | --- | --- |
| An LPCM `sample_rate` of 0 with binaural output divided by zero in the HRIR resampler: a ~70-byte stream aborted the process through the C ABI. Rates of 48000·k up to ~60 MHz cost GBs per renderer. | fix: reject codec sample rates the spec does not allow; fix(binaural): reject zero and very high resampling rates | `regressions.rs::lpcm_sample_rate_zero_rejected`, `codec_config_rejects_unsupported_sample_rates`, `zero_and_huge_rates_unsupported`, `unsupported_sample_rates_return_null` |
| Decoded frames were never checked against `num_samples_per_frame`. The batch decoder panicked on mismatched substream lengths, and the stream decoder padded, truncated and drifted. | fix(dec): require each decoded frame to match the codec config | `regressions.rs::decoded_frame_length_must_match_codec_config` |
| One bad OBU stopped the stream decoder for good: every later `decode()` re-parsed it and failed again. | fix(stream): consume an OBU that fails instead of retrying it forever | `stream_recovers_after_a_corrupt_frame`, `stream_drops_input_it_cannot_resynchronize` |
| A 2-byte OBU (`[0x32, 0x00]`) read as "incomplete", so the stream decoder returned `Ok` forever with no output. | fix(obu): report a body too short for its flagged fields as InvalidObuSize | `body_too_short_for_flagged_fields_is_invalid_size`, `stream_recovers_after_a_too_short_obu` |
| A unit that never completed (or a duplicated element) buffered without limit: 12 KB of input grew to 65 MB. | fix(stream): bound buffering when a temporal unit never completes; fix(dec): decode every use of an element; reject shared substream IDs | `incomplete_units_do_not_accumulate`, `misaligned_delimiter_resynchronizes`, `element_used_twice_decodes`, `elements_sharing_a_substream_rejected` |
| A recon-gain block for an element without recon-gain layers expanded into billions of zero-byte subblocks (OOM). | fix(params): merge empty recon-gain subblocks instead of expanding them | `empty_recon_gain_subblocks_are_merged` (the old code runs out of memory rather than failing) |
| The rendering-config probe re-scanned to the end of the OBU for every element: quadratic parse time (608 KB took ~29 s). | fix(obu): parse the rendering-config extension only within its window | `rendering_config_probe_is_linear` |
| List pre-allocation was bounded by input bytes, not memory: a 16 MB OBU reserved 5.6 GB. | fix(obu): cap list pre-allocation by memory, not just by input bytes | `bounded_vec_reservation_is_capped`, `projection_matrix_checked_before_allocation` |
| The binaural convolver partitioned its filters by the frame size: one-sample frames cost ~3000x more per sample. | fix(binaural): bound convolution cost and memory for any frame size | `small_frame_channel_matches_direct_convolution`, `short_frames_render_like_long_frames` |
| symphonia's FLAC decoder panicked on frame headers that disagree with the substream. | fix(codecs): check FLAC frame headers before symphonia decodes them | `flac_frame_header_mismatch_is_an_error`, `frame_header_fields` |
| Any panic in the C ABI aborted the host process. | fix(capi): contain panics instead of aborting the host process | `panic_is_contained_and_poisons_the_handle` |
| Arithmetic that panicked with overflow checks: Bezier `ct * ct`, cursor sample counts, shrinking scalable layers. | fix(params): evaluate Bezier mix gains in f64; fix(dec): saturate gain and position cursor sample counts; fix(dec): reject scalable layers that remove channels | `bezier_long_subblock_does_not_overflow`, `gain_cursor_huge_durations_saturate`, `position_cursor_huge_durations_saturate`, `shrinking_layers_rejected_without_underflow`, `shrinking_layers_are_invalid` |

## Possible upstream issues

These looked wrong in the projects we port from or depend on. We have not
filed them yet; each needs a check against the latest upstream code first.

| Project | Issue | Evidence | Our handling |
| --- | --- | --- | --- |
| google/obr | `Resampler::AreSampleRatesSupported` checks for zero rates only with `DCHECK_GT`. In release builds a rate of 0 passes, because `FindGcd(48000, 0)` is 48000. Our port inherited the hole and divided by zero right after. | `obr/ambisonic_binaural_decoder/resampler.cc` | Rates are validated at parse time and in `rates_supported`. |
| google/obr | Filters are partitioned by the buffer size, so the cost per sample grows sharply for small buffers (~3000x at 1 sample versus 960). | Design of `PartitionedFftFilter` | A fixed 64-sample block for frames under 64 samples. |
| google/obr | `kLayout9_1_6_ch` puts speakers at L/R 30°, wide 60° and tops 30/90/150°. IAMF's 9.1.6 is the BS.2051 System H subset (FL/FR 60°, FLc/FRc 30°, tops 45/90/135°). Mapping IAMF 9.1.6 onto it would misplace speakers. | `obr/renderer/loudspeaker_layouts.h`; IAMF spec §3.6.2 table | We use the BS.2051-H positions. iamf-tools does not binauralize 9.1.6 today. |
| AOMediaCodec/iamf-tools | `ElementGainOffsetConfig::CreateRangeType` requires `min <= default <= max` on the coded values. Spec v2.0 §3.7.1.1 defines min and max relative to the default, so valid ranges are rejected. | `iamf/obu/element_gain_offset_config.cc` | We follow the spec (a deviation from our match-iamf-tools rule). |
| AOMediaCodec/iamf-tools | An unknown position parameter type makes the rendering-config extension opaque and keeps the mix. The spec says parsers SHALL ignore such a mix presentation. | Matches our earlier parser, which mirrored iamf-tools | Unchanged (matches iamf-tools); see [open items](#open-items). |
| pdeljanov/symphonia 0.5 | The FLAC decoder panics (asserts, also in release) on a frame whose channel count or block size exceeds what STREAMINFO declares, instead of returning an error. | `symphonia-core` `audio.rs` assertion; reproduced with test_000073 | We check frame headers first and catch codec panics. |
| opus-decoder crate | Arithmetic panics on adversarial packets (e.g. `extract_collapse_mask` shift overflow with overflow checks). | Existing `catch_unwind` in our Opus adapter | Already contained. |
| libiamf / obr reference WAVs | About 50% of binaural reference samples sit exactly 1 LSB above ours, never below, which suggests the references are floored rather than rounded. | `tools/iamfdec/tests/binaural.rs` measurements | No change; we stay within 2 LSB. |
| AOMediaCodec/roar | (Known, already documented in ARCHITECTURE.md.) Dual-LFE re-insertion for sound system H compares the source index instead of the destination index. | `ambisonic_to_channel_renderer.rs` | `iamf-roar` refuses scene-based elements to H. |

## Checked, no change

- **9.1.6 binaural speakers.** The review flagged that they differ from
  obr's table. The spec defines 9.1.6 as a subset of BS.2051 System H,
  which is what we use (see the obr row above).
- **The hand-rolled FFT** from 95321a5 is correct: the maximum bin error
  is 1.9e-5 against a naive DFT, and binaural output stays within 2 LSB of
  obr.
- **Demixer equations, recon-gain smoothing, the projection matrix, mix
  selection (§7.4.1), trims, output channel permutations and the C ABI
  pointer handling** were reviewed and are correct.

## Open items

- **Unknown position parameter types** (row above): the spec says to
  ignore the whole mix presentation. We still match iamf-tools. Decide
  whether to follow the spec and surface an "unsupported" flag.
- **`num_parameters` on object elements:** the parser rejects an object
  element with parameters, but the spec says parsers SHALL support any
  value. Future parameter types would make such elements fail.
- **The OAR revision of `matrices.rs` is not recorded.**
  `tools/extract_matrices.py` takes a checkout path. Pin and record the
  revision the next time the tables are regenerated.
- **Panics with `panic = "abort"`:** the C ABI now contains panics, but
  builds with `panic = "abort"` (Chromium's) still abort. The nightly
  fuzzing is the safety net there.
- **Error offsets** in `iamf_obu::Error` are relative to the OBU body or
  sub-reader, not absolute as `ByteReader::position`'s docs suggest. They
  only affect diagnostics.
